🎯 Strategic Planning

Infrastructure Roadmap

Quarterly

Build a multi-quarter infrastructure roadmap aligned with business objectives, migration milestones, and budget cycles.

You are an infrastructure strategy advisor. Build a [3-quarter / 4-quarter] infrastructure roadmap for our organisation. Context: - Current environment: [on-prem / hybrid / multi-cloud] running [key workloads, e.g. 120 VMs on VMware, 40 services on AWS EKS] - Business priorities for the year: [e.g. expand to APAC region, achieve SOC 2 Type II, reduce hosting costs by 20%] - Planned product launches or migrations: [e.g. migrate data warehouse to BigQuery by Q3, launch new SaaS tier in Q2] - Annual infrastructure budget: [$X] For each quarter, provide: 1. Key initiatives (max 3) with clear deliverables 2. Dependencies and prerequisites 3. Estimated budget allocation 4. Risk factors and mitigations 5. Success metrics / KPIs End with a summary timeline view and a list of decisions that need to be made in the next 30 days.
Pro Tip: Attach your current asset inventory or cloud billing CSV for more precise recommendations.

Create a vendor evaluation matrix for [category, e.g. observability platforms / CDN providers / container registries]. Vendors to compare: [Vendor A, Vendor B, Vendor C] Our requirements (rank by priority): 1. [e.g. Must support multi-region with <50ms latency] 2. [e.g. SSO/SAML integration, RBAC, audit logging] 3. Build vs Buy Decision Memo

As Needed

Structure a build-vs-buy analysis for an infrastructure capability with cost projections, risk assessment, and recommendation.

Write a build-vs-buy decision memo for [capability, e.g. internal developer platform / secrets management / log aggregation pipeline]. Context: - Problem statement: [what gap are we solving and why now] - Current workaround: [how the team handles this today] - Team capacity: [e.g. 2 senior SREs could dedicate 40% time for 2 quarters] - Buy candidates: [e.g. HashiCorp Vault Enterprise, AWS Secrets Manager, CyberArk] Structure the memo as: 1. Executive Summary (1 paragraph recommendation) 2. Build Option: scope, timeline, staffing, estimated cost (build + maintain over 3 years) 3. Buy Option(s): licensing, implementation cost, ongoing cost over 3 years 4. Comparison table: cost, time-to-value, maintenance burden, customisability, risk 5. Risk assessment for each path (technical, operational, organisational) 6. Recommendation with conditions (e.g. "Buy if budget is approved by Q2; build if not") Keep the tone executive-friendly. Max 2 pages equivalent.
Pro Tip: Include your internal engineering hourly cost rate for more accurate build-side estimates.
💰 Budget & Capacity

Cloud Cost Optimisation Report

Monthly

Analyse cloud spend data, identify waste, recommend right-sizing/reservations, project savings.

Analyse the following cloud cost data and produce a monthly optimisation report. Cloud provider: [AWS / Azure / GCP] Total spend this month: [$X] vs last month: [$Y] vs budget: [$Z] Top 5 cost centres/accounts: [list with spend amounts] Known changes this month: [e.g. launched new staging env, migrated DB to RDS] Produce: 1. Executive summary: month-over-month trend, budget variance, top driver of change 2. Top 10 waste items (idle resources, oversized instances, unattached volumes, unused IPs) with estimated monthly savings each 3. Right-sizing recommendations for compute and database with specific instance type changes 4. Reserved Instance / Savings Plan opportunities with break-even analysis 5. Cost anomalies that need investigation 6. 90-day savings forecast if all recommendations are implemented Format as a report I can forward to my VP with a summary table at the top.

Capacity Planning Forecast

Quarterly

Project infrastructure capacity needs based on growth trends, planned launches, and seasonal patterns.

Create a capacity planning forecast for the next [2 / 3 / 4] quarters. Current infrastructure footprint: - Compute: [e.g. 85 EC2 instances, average 62% CPU utilisation] - Storage: [e.g. 40TB S3, 12TB EBS, growing 8% monthly] - Database: [e.g. 3x RDS instances at 70% capacity, 1x DynamoDB table at 40K RCU] - Network: [e.g. 2Gbps average egress, peaking at 5Gbps during releases] Growth drivers: - User growth rate: [e.g. 15% QoQ] - Planned launches: [e.g. new mobile app in Q2, expansion to EU region in Q3] - Seasonal patterns: [e.g. 2x traffic during November-December] For each resource category, provide: 1. Current utilisation vs capacity ceiling 2. Projected demand curve per quarter 3. When we hit 80% threshold (action trigger) 4. Recommended scaling actions with timeline and cost 5. Risks if we under-provision Include a summary table with RAG status (Red/Amber/Green) per resource category per quarter.
Pro Tip: Paste in CloudWatch or Datadog utilisation exports for data-driven projections.

Budget Proposal for Leadership

Quarterly

Draft an executive-ready budget request for infrastructure investment with ROI justification.

Draft an executive budget proposal for infrastructure investment in [FY year / quarter]. Request summary: - Total additional budget requested: [$X] - Breakdown by category: [e.g. Cloud compute: $A, Security tooling: $B, Staffing: $C, Licensing: $D] Business justification: - Problems being solved: [e.g. current outage frequency, scaling limits, compliance gaps] - Business initiatives this enables: [e.g. EU expansion, new product tier, SOC 2 certification] - What happens if we don't invest: [e.g. expected downtime costs, inability to launch on time] Structure as: 1. Executive summary (3-4 sentences, lead with business impact) 2. Current state and gap analysis 3. Proposed investment breakdown with line items 4. Expected ROI / payback period for each major item 5. Implementation timeline 6. Risk of inaction (quantified where possible) 7. Approval ask and next steps Keep it under 2 pages. Tone: confident, data-driven, business-first.
📈 Operations & SLAs

SLA/SLO Review & Recommendation

Monthly

Review current SLA performance data, identify at-risk services, and propose target adjustments.

Conduct an SLA/SLO review based on the following performance data. Services and their current targets vs actuals: [Service A: SLO 99.95% uptime, actual 99.91%, error budget remaining: 12%] [Service B: SLO p99 latency <200ms, actual p99 285ms] [Service C: SLO 99.9% uptime, actual 99.97%, error budget remaining: 78%] Reporting period: [e.g. March 2026] Notable incidents: [brief list of major incidents and durations] Produce: 1. RAG-status dashboard summary for each service 2. Services breaching or at risk of breaching SLO, with root cause patterns 3. Error budget burn rate analysis: which services will exhaust budget at current rate 4. Recommended SLO adjustments (tighten where over-performing, relax where unrealistic) 5. Action items: what engineering work is needed to bring at-risk services back to green 6. Suggested talking points for the next ops review meeting

Incident Trend Analysis

Monthly

Analyse incident data over a period to identify systemic patterns, MTTR trends, and recommend structural improvements.

Analyse the following incident data and identify systemic trends. Period: [e.g. Q1 2026] Incident data: [Paste incident list: date, severity, service affected, duration, root cause category, MTTR] Provide: 1. Summary statistics: total incidents by severity, average MTTR by severity, trend vs previous period 2. Top 3 recurring root cause categories with frequency and cumulative downtime 3. Services with highest incident density and whether they share common infrastructure 4. MTTR trend analysis: are we getting faster or slower at resolution? Why? 5. Correlation analysis: time-of-day patterns, deployment correlation, on-call fatigue indicators 6. Top 5 structural recommendations to reduce incident volume (not just firefighting) 7. Proposed investment areas ranked by expected incident reduction impact Format for presentation to engineering leadership. Include a suggested slide structure.
Pro Tip: Export incident data from PagerDuty, Opsgenie, or your ITSM tool as CSV and paste it directly.

Disaster Recovery Plan Review

Quarterly

Audit DR plan against current architecture, identify gaps, and create a remediation roadmap.

Review our Disaster Recovery plan against current architecture and identify gaps. Current DR targets: - RTO: [e.g. 4 hours for Tier 1, 24 hours for Tier 2] - RPO: [e.g. 1 hour for databases, 24 hours for file storage] Architecture summary: - Primary region: [e.g. AWS us-east-1], DR region: [e.g. AWS us-west-2] - Critical services: [list with their replication strategy] - Backup schedule: [e.g. daily snapshots, hourly WAL shipping for Postgres] - Last DR test date and result: [e.g. tested Jan 2026, achieved RTO 6 hours (missed target)] Produce: 1. Gap analysis: where current capabilities fall short of RTO/RPO targets 2. Single points of failure not covered by DR plan 3. Services added since last DR review that lack DR coverage 4. DR test findings remediation status 5. Updated DR runbook checklist (step-by-step failover procedure) 6. Remediation roadmap with effort estimates and priority ranking 7. Recommended DR test schedule and scenario design for next quarter
💬 Team & Communication

Team Scaling Proposal

As Needed

Build a headcount request with role definitions, skills gap analysis, and phased hiring plan.

Build a team scaling proposal for my infrastructure/DevOps organisation. Current team: - Size: [e.g. 8 engineers], structure: [e.g. 2 SREs, 3 DevOps, 2 Network, 1 Security] - Current workload pressure points: [e.g. on-call rotation too thin, backlog growing in IaC migration, no dedicated capacity for security initiatives] Growth drivers: - Upcoming projects: [e.g. Kubernetes migration, multi-region expansion, new compliance requirements] - Expected timeline: [e.g. all must be delivered within 12 months] - Business context: [e.g. company growing from 200 to 350 engineers, 3 new product teams being formed] Produce: 1. Skills gap analysis: what capabilities we lack vs what we need 2. Proposed new roles (title, level, key responsibilities, must-have skills) 3. Phased hiring plan across [3 / 4] quarters with justification for sequencing 4. Cost estimate per role (salary band + tooling/overhead) 5. Alternative to hiring: what could we outsource or automate instead 6. Impact analysis: what we can deliver with vs without additional headcount 7. Org chart: proposed team structure after scaling Format as an executive-ready proposal I can present to VP of Engineering.

Executive Infrastructure Brief

Weekly

Summarise infrastructure health, ongoing projects, and risk items for C-suite consumption.

Write a weekly executive infrastructure brief for C-suite distribution. This week's data: - Uptime: [e.g. 99.98% across production services] - Incidents: [e.g. 2 SEV-3 incidents, 0 SEV-1/2, details: ...] - Active projects status: [Project A: on track, 60% complete, ETA Q2] [Project B: at risk, blocked on vendor contract, need decision by Friday] [Project C: completed this week, now in monitoring phase] - Cost: [e.g. $X MTD, tracking 5% under budget] - Security: [e.g. 0 critical vulnerabilities, patch compliance at 94%] Format as: 1. TL;DR (3 bullet points max, biggest wins and risks) 2. Health dashboard (RAG status for: Availability, Performance, Security, Cost, Projects) 3. Key accomplishments this week 4. Risks and blockers needing leadership attention (with specific asks) 5. Next week priorities Keep it to one screen length. No jargon. Lead with what matters to the business.
Pro Tip: Create a template version once, then each week just update the raw data and re-run.

Post-Incident Executive Summary

As Needed

Transform a technical post-mortem into a non-technical executive summary with business impact and prevention plan.

Transform this technical post-mortem into an executive-ready incident summary. Technical post-mortem: [Paste the full technical post-mortem document here, including timeline, root cause, and action items] Additional context: - Customer-facing impact: [e.g. 12,000 users affected, checkout flow unavailable for 47 minutes] - Revenue impact: [e.g. estimated $X in lost transactions] - SLA implications: [e.g. this consumed 60% of our remaining monthly error budget] - Media/customer complaints: [e.g. 3 enterprise customer escalations, 45 support tickets] Produce: 1. Executive summary (5 sentences max: what happened, who was affected, how we fixed it) 2. Business impact (quantified: users, revenue, reputation) 3. Root cause in plain language (no technical jargon) 4. What we're doing to prevent recurrence (max 5 action items with owners and dates) 5. What leadership needs to know or decide 6. Confidence level that this won't recur (and why) Tone: accountable, transparent, forward-looking. No blame. Max 1 page.
