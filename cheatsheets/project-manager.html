📅 Planning & Scheduling

Project Kickoff Plan

Per Project

When you've just been handed a new project and need to hit the ground running with a structured kickoff.

I'm kicking off a new project. Here are the rough details: Project name: [e.g. Customer Portal Redesign] Sponsor / client: [e.g. VP of Product, Sarah Lin] High-level objective: [e.g. Rebuild the self-service portal to reduce support tickets by 40%] Estimated duration: [e.g. 16 weeks] Key teams involved: [e.g. Frontend, Backend, UX, QA, DevOps] Known constraints: [e.g. Must launch before Q3 sales cycle; no additional headcount] Budget range: [e.g. $250K including contractors] Please generate: 1. A kickoff meeting agenda (60 min) with time-boxed sections 2. A RACI matrix for the core workstreams 3. A milestone timeline with key dates and dependencies 4. A communication plan (who gets what update, how often, via which channel) 5. A list of open questions to resolve in the first week Format everything in clean tables and bullet points ready to paste into Confluence.
Pro Tip: Paste the project charter or SOW directly after this prompt for even more tailored output. Claude will extract scope, assumptions, and risks automatically.

Work Breakdown Structure (WBS)

Per Project

When you need to decompose a project scope into manageable work packages for estimation and assignment.

I need a Work Breakdown Structure for the following project: Project: [e.g. Data Platform Migration from On-Prem SQL Server to Azure Synapse] Scope summary: [e.g. Migrate 12 production databases, rebuild ETL pipelines, retrain analysts, decommission legacy servers] Number of team members: [e.g. 8 engineers + 2 data analysts] Target completion: [e.g. 20 weeks from kickoff] Please create a hierarchical WBS with: - Level 1: Major deliverables / phases - Level 2: Work packages under each deliverable - Level 3: Individual tasks with estimated effort in person-days - Suggested owner role for each task - Flag any tasks that are likely on the critical path Present this as an indented outline with effort estimates in a table format.

Dependency Mapping

Per Project

When your task list is getting complex and you need to visualise what blocks what before committing to dates.

Here is my current task list for the project. Please analyse it for dependencies, identify the critical path, and flag scheduling risks. Project: [e.g. ERP System Upgrade v4.2] Tasks: [Paste your task list here, e.g.: - T1: Requirements sign-off (5d) - T2: Database schema migration (8d) - T3: API endpoint updates (10d) - T4: UI redesign for new modules (12d) - T5: Integration testing (7d) - T6: UAT with business users (5d) - T7: Production deployment (2d) - T8: Training materials creation (6d)] For each task, determine: 1. Predecessors (which tasks must finish first) 2. Whether it's on the critical path 3. Float / slack available 4. Cross-team dependencies (flag if a different team owns a predecessor) Also flag any scheduling conflicts or resource contention risks. Present as a dependency table and a text-based critical path diagram.
Pro Tip: Export your Jira or Azure DevOps task list as CSV and paste it directly. Claude can parse structured data and give more accurate dependency analysis.
📈 Tracking & Reporting

Weekly Status Report

Weekly

Every Friday when you need to transform your messy notes into a polished status update for stakeholders.

Transform my raw project notes into a professional weekly status report. Project: [e.g. Cloud Infrastructure Modernisation] Reporting period: [e.g. 14 Apr - 18 Apr 2026] Overall health last week: [e.g. Amber] Raw notes: [e.g. - Finished VPC peering setup on Tuesday, took longer than expected due to firewall rule conflicts - Jenkins pipeline migration is 60% done, Mike found some plugins that won't work in the new version - Stakeholder demo went well, VP liked the dashboard mockups - Budget tracking shows we're 8% over on contractor hours - QA environment still not provisioned, waiting on IT ticket #4521 - New risk: key architect Sarah is being pulled onto another project 2 days/week starting next sprint] Please produce a status report with: 1. RAG status (Red/Amber/Green) with one-line justification 2. Key accomplishments this week (bullet points) 3. Upcoming milestones (next 2 weeks) 4. Risks and issues table (ID, description, probability, impact, mitigation, owner) 5. Decisions needed from leadership 6. Resource concerns Keep it concise. Maximum one page when printed.

Risk Register Update

Weekly

When it's time to review and update your project risk register with current intel from the team.

I need to update my project risk register. Here is the current register and new information from this week. Project: [e.g. Payment Gateway Integration] Current risk register: [Paste your existing risk register or list known risks, e.g.: - R1: Third-party API rate limits may bottleneck peak traffic (Prob: Medium, Impact: High) - R2: PCI compliance audit timeline unclear (Prob: High, Impact: High) - R3: Key developer leaving in 6 weeks (Prob: Confirmed, Impact: Medium)] New information this week: [e.g. - Vendor confirmed API rate limit of 500 req/sec, we need 800 at peak - Compliance team scheduled audit for May 15 - Junior developer completed knowledge transfer sessions with departing dev - New concern: staging environment SSL certificate expires next week] For each risk, please: 1. Update probability and impact based on new info 2. Recalculate risk score (probability x impact on 1-5 scale) 3. Update mitigation plan and status 4. Assign or confirm owner 5. Add any new risks identified 6. Mark any risks that can be closed Format as a table sorted by risk score (highest first).

Milestone Variance Analysis

Monthly

When milestones are slipping and you need to quantify the variance, explain it, and propose a recovery plan.

Perform a milestone variance analysis for my project and recommend recovery actions. Project: [e.g. Mobile App v3.0 Launch] Milestone data: [e.g. | Milestone | Planned Date | Actual/Forecast Date | Status | | Requirements Complete | 01 Feb 2026 | 05 Feb 2026 | Complete | | Design Sign-off | 20 Feb 2026 | 28 Feb 2026 | Complete | | Backend API Ready | 15 Mar 2026 | 25 Mar 2026 | Complete | | Frontend Integration Done | 05 Apr 2026 | 18 Apr 2026 | In Progress| | QA Testing Complete | 25 Apr 2026 | 10 May 2026 | Forecast | | Go-Live | 05 May 2026 | 22 May 2026 | Forecast |] Please provide: 1. Variance for each milestone (in working days, positive = late) 2. Cumulative slippage trend analysis 3. Root cause summary for the slippage pattern 4. Impact on the overall project deadline and dependent projects 5. Three recovery options ranked by feasibility (e.g., scope reduction, resource injection, parallel workstreams) 6. Recommended option with justification Include a simple text-based trend chart if possible.
Pro Tip: Paste data from your project schedule tool (MS Project, Smartsheet) directly. The more historical data you provide, the better the trend analysis.
💬 Stakeholder Communication

Executive Project Summary

Weekly

When leadership wants a quick, no-fluff summary they can scan in under 2 minutes.

Condense the following project details into a one-page executive summary for senior leadership. Project: [e.g. Enterprise Data Lake Implementation] Sponsor: [e.g. CTO, James Rivera] Overall status: [e.g. Amber - schedule risk] Budget status: [e.g. $1.2M of $1.5M spent, 78% through timeline] Detailed notes: [e.g. - Phase 1 (ingestion layer) complete and in production - Phase 2 (transformation pipelines) 70% done, 1 week behind schedule due to unexpected data quality issues in legacy CRM system - Phase 3 (analytics dashboards) not yet started, on track to begin May 1 - Team velocity has improved after adding senior data engineer - Dependency on InfoSec team for data classification policy is blocking Phase 2 completion - Successfully onboarded 3 business analyst teams as early adopters - Positive feedback from Finance team on prototype reports] Format the executive summary with: 1. One-paragraph project health overview (RAG with explanation) 2. Key metrics dashboard (budget, timeline, scope, quality - each with RAG) 3. Top 3 accomplishments this period 4. Top 3 risks requiring leadership attention 5. Decisions or support needed from executives 6. 30-day outlook Write in a direct, confident tone. No jargon. Assume the reader has 90 seconds.

Scope Change Request

As Needed

When a stakeholder asks for something new and you need to formally document the impact before agreeing.

Draft a formal scope change request document for the following proposed change. Project: [e.g. HR System Implementation] Change requested by: [e.g. VP of HR, Amanda Chen] Current project end date: [e.g. 30 Jun 2026] Current budget remaining: [e.g. $85,000] Change description: [e.g. Add a custom employee self-service module for benefits enrollment that was not in the original SOW. This includes a mobile-responsive form builder, integration with 3 insurance providers via API, and a manager approval workflow.] Known context: [e.g. - The team is currently at 90% capacity - QA phase was scheduled to start in 3 weeks - The benefits enrollment period is in October, so the module would need to be live by Sep 15 - Similar module took a partner company 6 weeks to build] Please generate a change request document with: 1. Change ID and title 2. Description of the change 3. Business justification 4. Impact analysis: timeline (new end date estimate), budget (additional cost), resources (additional effort), quality (risk to existing scope) 5. Alternatives considered (at least 2) 6. Recommendation (approve / defer / reject with rationale) 7. Approval signatures section (Sponsor, PM, Tech Lead) Use a professional document format.

Meeting Agenda & Minutes Generator

Daily

Before a meeting to create a focused agenda, then after to convert your raw notes into structured minutes with action items.

I have a project meeting coming up. First generate an agenda, then I'll give you my notes to convert into minutes. Meeting type: [e.g. Weekly project sync / Steering committee / Technical design review] Attendees: [e.g. PM (me), Tech Lead, 2 Senior Devs, QA Lead, Product Owner] Duration: [e.g. 45 minutes] Key topics to cover: [e.g. - Sprint 4 progress update and blockers - Decision needed on database vendor selection (Postgres vs Aurora) - QA environment provisioning delay - Upcoming client demo prep on Apr 25 - Resource conflict: 2 devs allocated to another project next week] Previous action items still open: [e.g. - @TechLead: Complete API performance benchmarks (due Apr 18, overdue) - @QA: Document test case coverage gaps (due Apr 20) - @PM: Escalate infrastructure ticket to IT director] Please generate: 1. A time-boxed agenda with owner for each topic 2. A suggested parking lot for topics that can wait After the meeting, I'll paste my raw notes and need you to produce: - Structured minutes with decisions made, action items (who, what, when), and items deferred to next meeting.
Pro Tip: Use Claude in two turns: first to generate the agenda, then paste your rough meeting notes to get polished minutes. This saves 30+ minutes per meeting.
🏆 Closure & Lessons Learned

Project Post-Mortem

Per Project

When a project wraps up (successfully or not) and the team needs a structured debrief before moving on.

Conduct a structured post-mortem analysis for a recently completed project. Project: [e.g. Client Onboarding Automation Platform] Duration: [e.g. Planned: 14 weeks, Actual: 19 weeks] Budget: [e.g. Planned: $320K, Actual: $395K] Team size: [e.g. 6 engineers, 1 designer, 1 QA] Outcome: [e.g. Delivered and in production, but 5 weeks late and 23% over budget. Client satisfaction score: 7/10] Key events during the project: [e.g. - Scope expanded twice after initial sign-off (added SSO integration, added audit logging) - Lead developer left in week 8, replacement took 2 weeks to onboard - Third-party API vendor changed their authentication model mid-project - QA found 47 critical bugs during UAT, 3x the typical rate - Client praised the UX design and overall system performance] Please generate a post-mortem document with: 1. Project scorecard (scope, schedule, budget, quality, stakeholder satisfaction - each rated) 2. What went well (with specific evidence) 3. What didn't go well (with root cause analysis for each item) 4. Systemic issues identified (patterns that could affect future projects) 5. Recommended process improvements (specific, actionable, with suggested owner) 6. Team kudos section (celebrate contributions) Tone should be blameless and constructive.

Lessons Learned Summary

Per Project

When you need to distil project experiences into reusable knowledge for the PMO and future project managers.

Extract actionable lessons learned from the following project data and team feedback. Format for our PMO knowledge base. Project: [e.g. Regulatory Compliance Platform Build] Industry: [e.g. Financial Services] Project type: [e.g. Greenfield development, fixed-price contract] Data sources: [e.g. Post-mortem findings: (paste from your post-mortem) Team retrospective notes: "Estimation was too optimistic for the compliance rules engine. We didn't account for the regulatory review cycle. Cross-team handoffs between frontend and backend were messy. The CI/CD pipeline saved us during crunch time. Client communication was excellent." Metrics: - Schedule variance: +35% (5 weeks late on 14-week plan) - Budget variance: +23% - Defect density: 4.2 bugs per KLOC (target was 2.0) - Team satisfaction: 6.5/10 - Client satisfaction: 7/10] Please produce a lessons learned summary with: 1. Executive summary (3 sentences) 2. Lessons organised by category: Estimation, Scope Management, Technical, Team, Communication, Vendor/Client 3. For each lesson: what happened, why it matters, specific recommendation for future projects 4. Quick-reference checklist that a PM can use when starting a similar project 5. Tags for knowledge base indexing Write in third person, objective tone suitable for a PMO library.
Pro Tip: Feed in multiple project post-mortems at once and ask Claude to identify patterns across projects. This surfaces systemic organisational issues that no single project review would catch.

Resource Utilisation Report

Monthly

When you need to analyse how your team's time is being spent and make a case for rebalancing or additional headcount.

Analyse the following team allocation data and produce a resource utilisation report with recommendations. Project(s): [e.g. Project Alpha, Project Beta, BAU Support] Reporting period: [e.g. March 2026] Team capacity: [e.g. 8 team members x 22 working days = 176 person-days available] Allocation data: [e.g. | Team Member | Project Alpha | Project Beta | BAU Support | PTO/Training | Total | | A. Kumar | 15d | 3d | 2d | 2d | 22d | | B. Patel | 8d | 8d | 4d | 2d | 22d | | C. Zhang | 20d | 0d | 2d | 0d | 22d | | D. Morrison | 5d | 12d | 5d | 0d | 22d | | E. Santos | 10d | 10d | 2d | 0d | 22d | | F. Nguyen | 0d | 5d | 15d | 2d | 22d | | G. Williams | 12d | 0d | 5d | 5d | 22d | | H. Davis | 3d | 18d | 1d | 0d | 22d |] Please produce: 1. Utilisation summary per person (% on project work vs BAU vs non-productive) 2. Over-utilised resources (>90% project allocation) with burnout risk flag 3. Under-utilised resources (<60% project allocation) with rebalancing suggestions 4. Project-level demand vs supply analysis 5. Recommendations for next month's allocation 6. Headcount justification if needed (data-backed) Include charts described in text format and a summary table.
